PART 1

Filters and Edges

1.1

Convolutions from Scratch

4-loop & 2-loop versionsO(H × W × K²)Matches scipy

I implemented 2D convolution two ways: with four nested loops (checking every output pixel and every kernel element) and with two loops (checking every output pixel but using NumPy to multiply the kernel and image patch all at once). Both flip the kernel before sliding it across the image, which is correct by definition. Both implementations have time complexity O(H × W × K²), since we process every output pixel and perform K² operations per pixel. The 2-loop version is faster in practice because NumPy's vectorized operations run in compiled C, while the 4-loop version executes K² separate Python multiplications per pixel.

Both my implementations match scipy.signal.convolve2d exactly (up to floating-point rounding). For the 9×9 box filter, the 2-loop version is much faster because NumPy multiplies all 81 kernel elements and the corresponding image patch in a single vectorized operation, while the 4-loop version does 81 separate multiplications. For tiny filters like Dx and Dy with only 2 elements each, the NumPy overhead is large relative to the work, so the two versions run at similar speed. scipy is fastest since it runs compiled C code.

1.2

Finite Difference Operator

Partial derivativesGradient magnitudeThreshold = 0.25

The partial derivatives Dx and Dy measure how fast the image intensity changes in the x and y directions. While on the other hand, the gradient magnitude combines these two derivatives to give a single measure of how fast the intensity changes in any direction. This gives a single number at each pixel that tells how strong the edge is, regardless of direction. High magnitude means a sharp change in intensity; low magnitude means a flat region.

I thresholded the gradient magnitude at 0.25 to get a binary edge image. At lower thresholds, the grass texture creates a lot of noise—many small speckles from fine detail. At higher thresholds, the edges of the cameraman and tripod start breaking up and disappearing.

Gradient magnitude: |∇I| = √( (∂I/∂x)² + (∂I/∂y)² )
1.3

Derivative of Gaussian (DoG) Filter

Gaussian: size 9, σ = 1.5Blur + derivative in one filterThreshold = 0.08

I created a 2D Gaussian kernel by taking a 1D Gaussian from cv2.getGaussianKernel() and taking its outer product with itself. I then convolved the Gaussian with Dx and Dy to create the Derivative of Gaussian filters. This lets me blur and take the derivative in one step instead of doing two separate convolutions. I got similar results using both methods.

The blurred version also produced much cleaner edges than the raw finite difference method because the Gaussian reduces some of the noise. I used a lower threshold of 0.08 for the smoothed image compared to 0.25 for the original.

PART 2

Applications

2.1

Image "Sharpening"

Unsharp mask filterα = 0.5, 1, 2, 4Best: α = 1–2

I used a Gaussian blur to keep the low-frequency parts of the image, which are the smoother features. When I subtract the blurred image from the original, I get the high-frequency parts, mainly the edges and fine details. I can then add some of those details back to the original using the unsharp mask to make the image look sharper.

When I use a small α, like 0.5, the sharpening is pretty subtle. I can see that the edges are a little clearer, but the image still looks natural. As I increase α, the edges and details become more noticeable. When I use a large value like 4, though, the sharpening starts to look too strong. I can see halos around some of the edges, and the noise also becomes more noticeable. For these images, I found that α = 1 or 2 gives a good balance between making the details clearer and keeping the image looking natural.

Unsharp mask: sharpened = f + α · (f − G ∗ f)
2.2

Hybrid Images

Two-point alignmentHigh-pass σ₁ = 5.0Low-pass σ₂ = 7.0

For my hybrid images, I combined the high-frequency parts of one image with the low-frequency parts of another. I first aligned each pair of images by matching two corresponding points, such as the eyes, so that the images were the same size and rotation. Then I used a Gaussian blur with σ₁ = 5.0 on one image and subtracted it from the original to get the high-frequency details. For the other image, I used a Gaussian blur with σ₂ = 7.0 to keep the low-frequency parts, and then added the two images together to create the hybrid.

I noticed that the result looks different depending on how far away I am from the image. When I look at it up close, I mostly see the high-frequency image because the sharper details stand out more. When I look at it from farther away, the high-frequency details are harder to see, so the low-frequency image becomes more noticeable. I also found that the σ values affect how much detail gets kept in each image. A smaller σ keeps more of the sharper details, while a larger σ smooths the image more. I chose σ₁ = 5.0 and σ₂ = 7.0 so that the two frequency ranges would be separated more and not overlap as much.

Hybrid: H = (f₁ − Gσ₁ ∗ f₁) + Gσ₂ ∗ f₂
2.3

Gaussian and Laplacian Stacks

No downsamplingσ doubles each levelSum of Laplacians = original

A stack is basically like a pyramid, except I don't downsample the image. Every level stays the same size as the original image. For the Gaussian stack, I blur the previous level again at each step, with σ doubling each time. This lets me look at the image at different scales while keeping everything at the same resolution. For the Laplacian stack, I take the difference between two neighboring Gaussian levels. This gives me the edges and details that are present at that particular scale. The last level is just the blurriest Gaussian level, which contains the coarsest features. If I add all of the Laplacian levels back together, I can reconstruct the original image.

The main difference between a stack and a pyramid is that a pyramid downsamples the image at each level, so each level gets smaller. A stack keeps the same image size at every level. This uses more memory, but I found it easier to use for blending since I don't have to resize the images between levels.

2.4

Multiresolution Blending

Laplacian stack per imageGaussian stack of maskStep & circular masks

To blend the two images together, I made a Laplacian stack for each image and a Gaussian stack for the mask. At each level, I used the mask at that level to decide how much of each image to keep, and then I added all the levels together at the end. Using the blurred mask helps make the transition between the two images smoother instead of having a really obvious seam.

For the oraple, I used a vertical step mask where the left side was the apple and the right side was the orange. After putting the mask through the Gaussian stack, the edge between the two images becomes more gradual, so the details near the seam blend together better. For my own blends with the dog and cat, I tried both a vertical seam and a circular mask. I found that the circular mask made the transition look more natural because the edges of the mask are softer.

Blend at level i: Li = Gi(M) · Li(A) + (1 − Gi(M)) · Li(B)
SUMMARY

What I Learned

This project taught me how useful frequency decomposition can be for image processing. I learned that instead of working with the whole image at once, I can separate it into different scales or frequency ranges and work with each part separately. With Laplacian stacks, for example, I can blend images at different scales instead of just trying to match the pixels directly. This made it easier to get a smoother transition between the images.

I also noticed that the pyramid idea came up in a lot of different parts of the project. I used a coarse-to-fine approach for image alignment, Gaussian blurs to separate low and high frequencies for sharpening, and Laplacian stacks to blend images at different scales. Seeing the same idea used in all of these different tasks helped me understand why pyramids are so useful in computer vision. Instead of trying to solve everything at the full image scale, I can break the problem down and work with the image at different levels.
